# LAB TODO 注释迁移设计

## 目标

将 `/Volumes/linux_code/OS-repo/OS-Course-Lab` 中学生实验代码的 `LAB* TODO` 注释移植到 `/Volumes/linux_code/OS-repo/chcore-source` 的完整实现中，方便对照实验填空位置与参考实现。

## 范围

- 来源限定为学生仓库 `Lab1` 至 `Lab5` 的代码文件。
- 迁移所有带实验编号的 `LAB* TODO BEGIN/END` 边界注释，包括 Lab5 文件中出现的 `LAB7 TODO` 标记。
- 同时迁移与对应填空直接关联的说明、提示、步骤和语义解释注释。
- 不迁移 `Pages` 文档内容、版权头、普通通用注释或 Lab6 中与实验填空无关的普通 `TODO`。
- 目标仓库只增加注释；不得修改、删除、移动或重新格式化已有实现代码。

## 映射方法

逐个 TODO 区域使用语义锚点定位，而不依赖行号。锚点优先使用函数名、TODO 前后的稳定语句、控制流结构和已有注释。若学生代码与完整实现存在差异，则根据该实验要求对应的完整实现语义确定边界，使 `BEGIN/END` 包围学生原本应填写的完整实现范围。

与 TODO 直接相关的说明注释按其原始语义放置：描述整个填空区域的注释放在 `BEGIN` 后，描述特定语句或步骤的注释放在对应实现旁。注释文字和 LAB 编号保持来源仓库原样，仅在目标文件缩进需要时调整前导空白。

如果某处无法唯一映射，则不猜测位置，保留文件不变并在结果中列为未映射项。

## 变更流程

1. 枚举学生仓库中所有真正的 LAB 编号 TODO 标记及其关联说明注释。
2. 将每个来源文件映射到完整源码的对应文件。
3. 逐区域用代码语义锚点确定完整实现中的插入位置。
4. 只插入 TODO 边界与关联实验说明注释。
5. 检查覆盖率、位置和非注释内容不变性。

## 验证标准

- 来源范围内的每一处 LAB TODO 标记均对应一个已迁移项或明确列出的未映射项。
- 每一对 `BEGIN/END` 保持配对并位于正确函数或实现区域。
- `git diff` 中除新增注释行外没有源码内容变化。
- 移除新增注释后，每个目标文件与修改前的非注释内容完全一致。
- 不修改学生仓库，不引入构建产物，也不更改目标仓库中与本任务无关的文件。
